# 离线地图项目（amapoffline）代码结构说明文档

> 最后更新：2026-10-01
> 适用数据源：`public/china-20260930.pmtiles`（中国全境，矢量瓦片，zoom 0-14）

---

## 1. 项目概述

本项目是一个**纯前端离线矢量地图应用**，基于 React + Vite + MapLibre GL + PMTiles 构建。地图数据（矢量瓦片）与字体（glyph PBF）全部本地化存放于 `public/` 目录，浏览器通过自定义 `pmtiles://` 协议直接读取本地文件渲染地图，**无需任何在线地图服务或后端瓦片服务器**。

### 技术栈

| 技术 | 版本 | 用途 |
|---|---|---|
| React | ^18.3.1 | UI 框架 |
| Vite | ^5.3.1 | 构建工具 / 开发服务器 |
| maplibre-gl | ^6.11.2 | 地图渲染引擎（开源 Mapbox GL 分支） |
| pmtiles | ^4.5.0 | PMTiles 协议解析（浏览器端读取单文件瓦片归档） |
| playwright-core | ^1.63.0（dev） | 自动化浏览器验证脚本 |
| ESLint | ^8.57.0（dev） | 代码检查 |

### 核心特点

- **单文件瓦片归档**：使用 `.pmtiles` 格式，一个文件包含全部矢量瓦片（z0-z14），便于分发与部署
- **OpenMapTiles schema**：瓦片由 tilemaker 按 OpenMapTiles 规范生成，包含 `landcover`、`landuse`、`water`、`building`、`transportation`、`place`、`poi` 等标准图层
- **离线字体渲染**：文字标注使用本地 Noto Sans glyph PBF 分片，中文/拉丁文字均可离线渲染
- **数据范围**：中国全境（`BOUNDS ≈ [73.5, 18.1, 135.1, 53.6]`），默认中心为北京天安门 `[116.3974, 39.9097]`

## 3. 源码模块详解

### 3.1 `src/main.jsx` — 应用入口

- 使用 `ReactDOM.createRoot` 以 React 18 StrictMode 挂载 `<App />` 到 `index.html` 的 `#root` 节点
- 引入 `index.css` 全局样式

### 3.2 `src/App.jsx` — PMTiles 协议注册（关键）

```jsx
setWorkerUrl(workerUrl);                          // maplibre-gl v6 必须显式指定 worker
const protocol = new Protocol();
addProtocol('pmtiles', protocol.tile);            // 注册 pmtiles:// 协议
return () => removeProtocol('pmtiles');           // 卸载时移除协议
```

- maplibre-gl v6 的 worker 不能自动解析，需通过 `?worker&url` 导入 `maplibre-gl-worker.mjs` 并调用 `setWorkerUrl`
- `pmtiles` 包的 `Protocol` 类让 MapLibre 能以 `pmtiles:///文件名` 形式的 URL 直接从 `public/`（同源静态目录）按需读取瓦片，实现零后端离线渲染
- 组件卸载时移除协议，避免重复注册

### 3.3 `src/OfflineMap.jsx` — 地图组件

| 配置项 | 值 | 说明 |
|---|---|---|
| `style` | `offlineStyle` | 来自 `mapStyle.js` 的离线样式 |
| `center` | `[116.3974, 39.9097]` | 北京天安门 |
| `zoom` | `11` | 初始缩放级别 |
| `minZoom` / `maxZoom` | `0` / `14` | 瓦片数据最高到 z14 |
| `maxBounds` | `BOUNDS` 外扩 0.5°/0.4° | 限制视野在中国全境内 |
| `attributionControl` | `{ compact: true }` | 紧凑型署名控件 |

- **控件**：右上 `NavigationControl`（支持 pitch 可视化）、左下 `ScaleControl`（公制比例尺）
- **调试**：开发模式下挂载 `window.__offlineMap`，供 `verify-browser.mjs` 脚本远程 `jumpTo` 控制
- **生命周期**：`useEffect` 中创建 Map，清理函数调用 `map.remove()` 防止内存泄漏
- `BOUNDS = [73.5, 18.1, 135.1, 53.6]` 为中国全境近似范围，建议以 `pmtiles` 头信息实际 `bbox` 为准微调

### 3.4 `src/mapStyle.js` — 离线地图样式（核心）

导出内容：

- `TILESET`：瓦片文件名 `'china-20260930.pmtiles'`（数据源单一入口，换数据只改此处）
- `offlineStyle`：完整 MapLibre Style Spec v8 对象

样式结构：

```js
{
  version: 8,
  glyphs: '/fonts/{fontstack}/{range}.pbf',     // 本地字体分片
  sources: {
    shanghai: {                                  // 注意：source id 仍为历史命名 "shanghai"
      type: 'vector',
      url: `pmtiles:///${TILESET}`,              // pmtiles:// 协议 + public/ 相对路径
      attribution: '© OpenStreetMap contributors',
    },
  },
  layers: [ /* 约 40+ 个图层 */ ],
}
```

图层分组（自上而下绘制顺序）：

| 分组 | 图层内容 | source-layer |
|---|---|---|
| 背景 | 纸色底 `#f5f2ec` | — |
| 土地覆盖 | 冰川、沙地、农田、林地、草地 | `landcover` |
| 土地利用/公园 | 学校/医疗/工业等用地、居住区、公园 | `landuse` / `park` |
| 水系 | 水面填充、河流 | `water` / `waterway` |
| 机场 | 机场面 | `aerodrome` |
| 建筑 | 3D 挤出（fill-extrusion） | `building` |
| 行政边界 | 边界线 | `boundary` |
| 铁路 | 铁路线 | `transportation` |
| 道路 | 小路 + 主干道（casing/fill 双层，按等级配色，按 zoom 过滤） | `transportation` |
| 机场跑道 | 跑道线 | `aeroway` |
| 水域名 | 湖泊/海湾名称 | `water_name` |
| 地名 | 按级别（国家/州/市/镇/村）+ zoom 控制显隐，`text-size` 按级别插值 | `place` |
| 道路名称 | 道路标牌式文字 | `transportation_name` |
| POI | 圆点 + 文字标签（z14+） | `poi` |
| 其他标签 | 机场名、门牌号、山峰（含高程） | `aerodrome_label` / `housenumber` / `mountain_peak` |

标注文字统一使用 `NotoSansRegular` / `NotoSansBold` 字体栈，文字字段以 `name:latin` 为主。

| 脚本 | 用法 | 说明 |

| `download-glyphs.mjs` | `node scripts/download-glyphs.mjs` | 从 openfreemap.org 下载 Noto Sans Regular/Bold 共 512 个 glyph 分片到 `public/fonts/`，含重试与 HTML 错误页校验 |

## 6. 数据流与渲染管线

```
浏览器请求 pmtiles:///china-20260930.pmtiles (由 mapStyle.js sources 定义)
        │
        ▼
pmtiles.Protocol (App.jsx 中 addProtocol 注册)
  ├── 按 HTTP Range 请求 public/china-20260930.pmtiles
  ├── 解析 pmtiles 归档索引 → 定位目标 z/x/y 瓦片
  └── 返回 MVT 矢量瓦片给 maplibre worker
        │
        ▼
maplibre-gl 渲染引擎
  ├── worker 解析 MVT (setWorkerUrl 指定)
  ├── 按 offlineStyle 的 layers 过滤/配色/分级渲染
  └── 文字标注请求 /fonts/{fontstack}/{range}.pbf (本地 Noto Sans)
        │
        ▼
React 组件 (OfflineMap.jsx) 挂载容器 div (100vw × 100vh)
```

## 7. 更换 / 扩展数据指引

1. **更换瓦片数据**：将新 `.pmtiles` 文件放入 `public/`，修改 `src/mapStyle.js` 中的 `TILESET` 常量即可（历史遗留：source id 与样式 name 仍叫 `shanghai`，不影响功能，可择机重命名）
2. **更新视野范围**：运行 `node scripts/inspect-pmtiles.mjs` 获取真实 bbox，同步修改 `OfflineMap.jsx` 中的 `BOUNDS`
3. **新增图层**：在 `mapStyle.js` 的 `layers` 数组中按绘制顺序追加，`source-layer` 需与 tilemaker 生成的 OpenMapTiles 图层名一致
4. **新增字体**：运行 `download-glyphs.mjs` 扩展字体栈，并在图层 `text-font` 中引用
5. **高德 SDK**：`public/amap/` 下的离线高德 JS API 为备用方案，当前主流程（离线 PMTiles 渲染）未引用

## 8. 已知问题与建议

| 问题 | 说明 | 建议 |
|---|---|---|
| 命名遗留 | source id `shanghai`、样式名 `Shanghai Offline`，与当前全国数据不符 | 重命名为 `china` / `China Offline`（需同步修改所有 layer 的 `source` 字段） |
| `BOUNDS` 为近似值 | 中国全境外扩值未经头信息核对 | 用 `inspect-pmtiles.mjs` 输出的 bbox 校准 |
| 大文件加载 | 全国 z0-z14 单文件体积较大，首次加载依赖 HTTP Range 支持（开发服务器与静态托管均支持，但 file:// 协议不可用） | 部署时使用支持 Range 的 HTTP 服务 |
| 硬编码浏览器路径 | `verify-browser.mjs` 依赖本机 Chrome 路径 | 改为环境变量或 `channel: 'chrome'` |
| 模板遗留文件 | `App.css`、`assets/`、`README.md` 为 Vite 模板内容 | 清理或替换为本说明文档 |
